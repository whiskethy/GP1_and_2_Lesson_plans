### Driving Question

How do you turn an idea into code a machine can run — and why does C++ make that harder and more powerful than Blueprint?

### Unit Narrative

The "now you write real code" unit. Students leave Blueprint-only thinking and build C++ foundations: what C++ is, how the build pipeline works, syntax and structure, data types, variables, functions, conditionals, loops, and scope. Each concept gets its own content day plus a practice day. Visual Studio and GitHub are set up mid-unit so students use real tooling for the second half. The unit closes with a Code Read trace on a short console program — the first instance of the skill that becomes the course spine. Sub days and a cancelled field trip compress the calendar; content days are never sub days.

### Enduring Understandings

1. C++ is compiled, not interpreted. The build pipeline (editor → compiler → linker → executable) explains why error messages look the way they do and why Blueprint "just works" by comparison.
2. Every program has structure: `#include`, `main()`, statements, blocks. You cannot read or debug what you cannot parse.
3. Variables, functions, conditionals, and loops are the four pillars of procedural logic. Every C++ program, including Unreal C++, is built from them.
4. Reading code you did not write is a skill you build, not a talent you have. The Code Read is the spine of this course.
