### Driving Question

Can you read, modify, and commit C++ code in Unreal without a tutorial holding your hand?

### Unit Narrative

The "prove it" unit. Students apply everything from Units 1–3 to modify an existing Roll-A-Ball project written in C++. Day 1 is a Code Read on PlayerBall.cpp — building on the .h trace from Unit 3. Day 2 is guided practice: fill in missing functions and fix seeded bugs. Day 3 is add-a-feature and independent practice. Day 4 is the final commit and deliverable demo. The VS+GitHub workflow was already set up in Unit 1, so no Build Guide day is needed. The unit is compressed from the original 8 meetings because students enter with stronger fundamentals from a longer Unit 1, and the Code Read on PlayerBall.cpp rides on Unit 3's pointer work.

### Enduring Understandings

1. Reading code you did not write is the prerequisite for modifying it. The Code Read on PlayerBall.cpp is the same skill as Unit 3's .h trace, now applied to implementation code.
2. Modifying existing code is how professional C++ development works in Unreal. You rarely write from scratch; you read, understand, and change.
3. A working commit is the deliverable. Code that compiles on your machine but is not pushed does not count.
