## Structure

1. Exemplar, full run-through (5-8 min) - the same clip from Day 32's buffer, now in front of the whole room. Let it read as a game, not a tutorial. Then say it plainly: this is the target, and it is built in steps, one video per day.
2. GitHub slides, Nick's existing deck, cut to the flow that matters (10 min): what a repo is, what clone does, what commit means (a save with a label, not just save), what push does (it leaves your computer). Keep to one worked example. This is the new-idea block of the day.
3. Test assignment walkthrough (5 min): what the assignment is (a repo with one file), what done looks like tonight (a pushed commit with the secret phrase), what NOT to put in (your name, anyone else's info).
4. Guided start on the assignment (15-18 min, circulating): Nick does step 1 on the projector, students do each step after him. Steps: open the assignment link, accept it (Classroom's assignment-accept flow), open GitHub Desktop, clone the repo, open in VS Code, type the secret phrase, save, commit with a written message, push.
5. Exit ticket (5 min). Unfinished students pick up at commit-or-push where they are Monday's buffer; nobody goes home broken.

## Exit ticket

1. What's the difference between commit and push? One sentence - which one sends it to the internet?
2. What did you have working by end of class: account, clone, secret phrase typed, commit, or push? Name the last step you finished.
3. What's one thing you expect GitHub Desktop to be useful for once the project starts (guessing from the slides is fine)?

**Exit ticket mastery criteria:** Q1: push is the one that leaves the machine; commit is local. If both land reversed, they misnamed it and need re-teach tomorrow, not a wrong answer. Q2: any named step counts; the last-step question builds the Tuesday Do Now's honest baseline. Q3: any plausible workflow use - version history, undo, backup, sharing - counts; "I don't know" gets a second look at the slides tomorrow.

## Differentiation & Accommodations

- **Engagement:** the exemplar carries the pitch; the GitHub assignment is small enough to finish in one sitting, so the first win is today, not "you'll see why."
- **Representation:** Nick's slides + projector walkthrough running in parallel; the change-list pane in GitHub Desktop is shown on the projector mid-flow so the abstract "commit" lands against a real visual.
- **Action & Expression:** students who finish push early help a peer clone; the fastest way to cement the cycle is watching someone else trip on it.
- **Accommodations:** students who did not sign up Thursday use this block's first minute to create the account instead of accepting the assignment, then rejoin at clone (or clone tomorrow during the Day 34 buffer). One-on-one help goes to whoever missed the verification email.
