# GP2 Q1 Day 15 — Functions + Variables Practice

**Date:** Mon 9/21 · **Unit:** 1 · **Chunk:** 11 (functions + variables practice)

> **Practice day.** No new instruction. Functions were introduced on Day 14. Today students clone their Variables Practice repo through Classmoji (clone only) and work the programs in Visual Studio.

## Learning Target

Write and call functions with parameters and return values, and declare variables with correct types, by completing the Variables Practice programs and pushing them to GitHub.

**Standards:** CSTA 3A-AP-13 (create prototypes that use algorithms to solve problems), 3A-CS-02 (use appropriate tools and abstractions in a development workflow) · ACT WME 402 (technical vocabulary), CLR 401 (close reading of text)

**Performance Task Connection:** Function fluency and variable declaration are the raw material of every program in this course. Students who cannot write a function with parameters cannot write the Roll-A-Ball movement code, and the Unit 1 Checkpoint assumes both are automatic.

## Do Now

| # | Type    | Question |
|---|---------|----------|
| 1 | Review  | Write the four parts of a function — return type, name, parameters, body — using `int add(int a, int b)` as your example. |
| 2 | Review  | What is the difference between `void` and a function that returns an `int`? When would you use each? |
| 3 | Preview | A game stores a player's name, age, and score. What data type would you pick for each one, and why? |

## Exit Ticket

1. Push your Variables Practice work to GitHub and paste your repo link.
2. Write a function called `double_score` that takes an `int` parameter and returns the value times two. Call it from `main()` and store the result in a variable you declared.
3. What data type would you use to store a player's health points, and why that one instead of `double`?

## Agenda

0. Enter class → open Visual Studio and log into GitHub Desktop. Do not clone anything yet.
1. Do Now review (5 min)
2. Classmoji walkthrough — accept Variables Practice, clone with GitHub Desktop (7 min)
3. Guided practice — first program (name-and-age) together, then one commit and push so the whole pipeline works for everyone (10 min)
4. Independent practice — remaining Variables Practice programs (rectangle-area, temperature-converter), teacher circulates (18 min)
5. Commit and push final work (3 min)
6. Exit Ticket (5 min)

## Differentiation & Accommodations

- **Engagement:** Game-themed framing on the practice programs (scores, health, hitboxes). Early finishers write a function of their own design — a dice roll, a damage calculator.
- **Representation:** C++ cheatsheet on every screen; Day 14's worked example on the board; annotated starter code in the template repo.
- **Action & Expression:** Exit ticket written or verbal. Students can show a working program on screen instead of pasting a link.
- **Accommodations:** Extended time. Starter code in the template for students who need scaffolding. Pair programming for the guided program only.
- **Student Voice:** Students choose which independent program to tackle first (rectangle-area or temperature-converter) and design their own early-finisher function.
